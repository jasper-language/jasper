# 第十一章：语言约定

本章收录**跨章节的语言级已定约定**：关键字分类、类型别名、计数语义、容器语义、
字符串相等性、相等/哈希协议、后缀自增/自减位置，以及 `@Extension` 扩展方法。

状态约定：本章条目都是**语言级决定**。凡涉及具体成员 API 的，若属标准库类型，
则由标准库提供；v1 编译器实现进度可能滞后，条目会单独标注。

---

## 11.1 关键字：软关键字、硬保留、保留但未启用

### 真软关键字

lexer **不**为它们定义 token；parser 用谓词匹配 `Identifier` 的文本，
因此它们只在被引用的语境生效，其他位置可作普通标识符。

| 软关键字 | 生效位置 | parser 规则 |
|----------|----------|-------------|
| `get` | 属性访问器 `{ get; set; }` | `softGet` |
| `set` | 属性访问器 `{ get; set; }` | `softSet` |
| `from` | from-import | `softFrom` |
| `onComplete` | `for-in` / `while` 循环正常完成子句 | `softOnComplete` |
| `onBreak` | `for-in` / `while` 循环被 break 打断子句 | `softOnBreak` |
| `onZeroRuns` | `for-in` / `while` 循环零次执行子句 | `softOnZeroRuns` |
| `where` | 泛型 `where` 子句 | `softWhere` |

例如 `function get()`、`p.onComplete(cb)`、`range.from` 都是合法标识符用法。
旧循环 `then { } else { }` 已移除；`else` 只属于 `if`。

### 有意保持硬保留

下列词是 lexer token（硬保留），**不**软化：

```text
as  cast  label  is  and  or  not
```

理由：它们出现在表达式中间（如 `cast x as T`），加谓词会引入预测不确定性。

符号式 `&&` / `||` / `!` 是正式写法；`and` / `or` / `not` 是可读别名，
但仍是保留字（收敛方案 A2）。

### 保留但未启用

下列词是**词法 token，但 parser 零引用**：

```text
raw shared weak auto unique atomic pointer handle locked delete destructor
```

当前裁决是**不启用 GC/所有权超集**，因此不应把它们写成"超集专用激活态"。
它们不能作普通标识符，也不接入任何有效语法。

## 11.2 类型别名表

短名是**固定宽度**别名，与平台无关（收敛方案 A5）：

| 短名 | 等价于 | 依据 |
|------|--------|------|
| `int` | `int32` | 跨目标无损；与 C/Java/C# 的 `int` 一致 |
| `uint` | `uint32` | 同上 |
| `float` | `float32` | C/Java/C#/GPU 的 `float` 一律单精度；64 位写 `float64` |
| `char` | `char32` | 32 位 Unicode scalar value |
| `byte` | `uint8` | 无符号字节；字节序列 `bytes` 的元素无符号 |

> 修订记录：原定 `int ≡ int64`、`uint ≡ uint64`，2026-10-14 改为 32 位，
> 理由是**多目标**（JS 目标上 int64 无自然映射）。

## 11.3 计数与长度语义

`.length` 的语义是**元素数（element count）**，按类型解释：

| 类型 | `.length` 含义 | 复杂度 |
|------|----------------|--------|
| 集合 / 数组（如 `T[]`） | 元素个数 | — |
| `string` | Unicode **码点数** | O(n) |
| `bytes` | 字节数 | — |

另有显式 API：

- `.byteLength()`：字节数。
- `.graphemeCount()`：字素簇（grapheme cluster）数，O(n)，**可裁剪**（不需要可移除）。

此外：

- **`.count` 已取消**，不再作为长度成员。
- **字符串不能用整数索引**：`s[i]` 非法（要按码点访问请用显式 API）。

> 实现状态：`array.length` v1 编译器**已实现**；
> `string` 的码点计数、`bytes` 字节数、`.byteLength()`、`.graphemeCount()` 属
> 运行时/标准库能力，v1 编译器**未实现**。

## 11.4 容器语义

- `T[]` 是**定长**类型，且与 `List<T>` 是**两个不同类型**，不可互换。
- `List<T>` / `MutableList<T>` 采用 Kotlin 式**只读/可变分家**。
- `Set`、`dict` **插入有序**：按插入顺序迭代。
- **无 COW**（copy-on-write，不做写时复制）。
- `const` 只约束**绑定**本身，**不约束容器内容**：
  `const xs: int32[]` 仍可修改元素。
- v1 **没有切片视图**（`xs[1:3]` 之类的视图语法不进入核心）。

> 具体容器类型（`List`、`Set`、`dict` 等）由标准库提供。

## 11.5 字符串相等性与 Unicode 规范化

- `==` 与 `hash` 按**原始码点序列**比较/计算，**不做隐式 Unicode 规范化**。
- 需要规范化时使用显式 API，例如 `s.normalized(NFC)`。

**显著位置的坑**：视觉相同、但规范化形式不同的字符串**不相等**；
把它们用作 `dict` 键时**互不相通**。

```jasper
// "é"（U+00E9）与 "e" + U+0301（组合重音）视觉相同，但不是同一个码点序列
var a: string = "\u00E9";
var b: string = "e\u0301";
// a == b 为 false；a.normalized(NFC) == b.normalized(NFC) 才为 true
```

> 实现状态：`normalized` 属标准库能力，v1 编译器未实现。

## 11.6 相等与哈希协议

- `Equatable`：定义相等性。
- `Hashable : Equatable`：在相等性之上定义哈希，`hash() -> int32`。
- `dict<K, V>` 要求键类型满足 `K: Hashable`。
- v1 采用**无条件一致性（unconditional coherence）**：一致性不可按实例化选择，
  因此**集合永不 `Hashable`**。
- **浮点不可作键**（`float32` / `float64` 不满足可作 `dict` 键的约束）。

> 实现状态：`Equatable` / `Hashable` 由标准库提供，v1 编译器未实现。

## 11.7 后缀自增/自减的合法位置

- **只支持后缀形式**：`x++` / `x--`；不支持前缀 `++x` / `--x`。
- 合法位置**恰好四处**：

  ```jasper
  i++;                    // ① 独立语句
  for (var i = 0; i < n; i++) { }   // ② for 更新子句
  y = x++;                // ③ 赋值右侧
  var y: T = x++;         // ④ 声明初始化器（且必须单独一个绑定）
  ```

- **非法**用法举例：`x++ + 1`、`(x++) * x++`、`x++++`。
- **一条语句最多一次自增/自减**；该约束由语法规则形态保证（而非运行时计数）。

> 实现状态：四处形态 v1 编译器**均已实现**（含 `var y: T = x++;` 取旧值并自增）。

## 11.8 `@Extension` 扩展方法

- 扩展以**注解函数**提供（`@Extension` 标注的函数成为扩展方法），
  而不是独立的 `extension` 关键字语法。
- 查找顺序：**成员优先于扩展**——若类型自身存在同名成员，则成员胜出。

> 实现状态：`@Extension` 属语言级决定，v1 编译器**未实现**。

## 11.9 源模式：`.jas` 与 `.jass`

- `.jas` 是默认的严格模块模式，只接受声明，不接受顶层可执行语句。
- `.jass` 是显式脚本入口模式，允许顶层可执行语句；前端把它们规范化为隐式
  `main(): void`，之后仍走统一 AST/TypeChecker/IR/后端。
- 模式只由扩展名或显式 API 选择，绝不从源码内容推断。
- 模式不通过 import 传染。脚本可导入严格模块；严格模块不能导入脚本入口。
- 脚本模式不开启动态类型、动态成员、隐式转换、运行时类型修改或第二套解释器，
  也不会自动获得文件、网络、进程等宿主能力。

两种模式使用同一套变量声明规则：

```jasper
var a = 10;
var b: int = 20;
var c: int;
c = 30;
```

禁止通过首次赋值隐式声明变量（`a = 10;`），禁止无类型且无初始化器的
`var d;`，也禁止改变已推断的变量类型。
