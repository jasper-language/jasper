# S4-A：协程上下文与结构化并发接口契约

> 状态：设计草案（2026-10-24 三项策略已获用户裁决）；供 S4-B 实现与验收使用。本文件不代表当前运行时已经支持这些能力。
> 适用范围：Jasper 语言级语义及运行时抽象；第一阶段 JVM Java 8，其他平台须保持相同可观察语义。

## 1. 三层职责与不变量

| 层 | 唯一职责 | 不负责 |
| --- | --- | --- |
| Coroutine | 保存执行状态、挂起、恢复及挂起点的协作检查 | 传播业务上下文、管理父子关系 |
| Context | 保存按键索引的不可变元素快照，派生时创建新快照 | 调度、授权、隐式关闭资源 |
| Structured Concurrency | 建立父子关系、等待所有子任务终止、取消传播、失败归并与回收 | 决定具体线程或平台调度策略 |

上下文快照不可变指映射与元素绑定不可变；Cancellation 的共享状态和 Job 的运行状态可以变化，但不得借此修改上下文映射。任务创建时冻结子上下文；后续父上下文映射的替换不追溯修改已创建子任务。父作用域正常退出必须等待全部子任务完成；异常退出必须先请求取消，再等待终止和清理。运行时不保证在不可中断的外部阻塞中强制终止任务。

## 2. 上下文元素类型表（全部为概念类型形状，非现有声明）

| 元素 | 类型形状（草案） | 创建方式 | 子任务继承判定 | 可见性 |
| --- | --- | --- | --- | --- |
| Job/Task 身份 | `JobId` + `TaskId` | 每次创建任务由运行时分配 | **必须派生**：子 JobId/TaskId 均为新值，parentJobId 指向创建它的父任务 JobId | 标识符可只读公开；Task 对象内部 |
| Cancellation | `CancellationToken`（父子链接的只读句柄） | 作用域创建根令牌，派生子令牌 | **必须派生**：父取消传给子；子取消不反向取消父，失败策略另行处理 | 公开查询与请求取消；内部状态私有 |
| Deadline | `Deadline?`（单调时钟截止点） | 作用域或显式子选项设定 | **取更严格**：子截止点 = min(父截止点, 显式子截止点)，空值视为无穷远 | 公开 |
| Executor | `ExecutorRef` | 根作用域绑定或显式子选项覆盖 | **默认继承**：未指定子 executor 则与父相同；指定则替换 | 公开选择能力；具体适配器内部 |
| Context Values | `ContextKey<T> → T` 的不可变映射 | 定义类型化键并显式授予传播许可 | **白名单继承**：只有声明可传播且满足快照安全规则的键才继承；其余均禁止自动继承 | 公开键/只读查询；内部键不可枚举 |
| Trace | `TraceContext`（traceId、spanId、采样标志） | 根入口建立 trace，子任务建立 span | **必须派生**：traceId 保持，子 spanId 新建，parentSpanId 为父 spanId | 公开只读 |
| Security Identity | `IdentityRef`（主体身份声明） | 可信入口验证后绑定 | **默认继承身份**：只复制主体标识；授权决策、权限缓存与能力令牌均不继承 | 公开受限只读 |
| Authorization | `AuthorizationDecision` | 在使用资源前针对动作和资源重新校验 | **禁止继承**：子任务任何受保护操作均重新授权 | 内部判定；结果不可跨任务复用 |
| Transaction | `TransactionHandle` | 资源作用域显式创建 | **禁止继承**：不进入通用子上下文；仅允许后续专用事务 API 明确约束共享 | 内部/专用资源 API |
| Connection | `ConnectionHandle` | 资源池显式租用 | **禁止继承**：子任务不能从通用上下文获得父连接 | 内部/专用资源 API |

上述 **10 项**构成 S4-A 的完整继承矩阵。对未知上下文键采用默认拒绝传播；只有显式声明可传播且值可安全共享/复制的键才继承。对同名键，显式子绑定覆盖父绑定，但不能绕过 Deadline、Cancellation、Identity/Authorization、事务及连接的专用规则。Identity 不能通过普通 Context Values 键伪装注入。

## 3. 继承规则的可判定补充

1. 子任务创建必得新 TaskId/JobId，且记录创建者的 JobId；标识符永不重用到仍存活的任务。
2. 子取消令牌与父建立单向链接；父取消必请求子取消，子主动取消不自动请求父取消。
3. Deadline 为父子最早有效截止点；子不能延长父期限。
4. Executor 未显式覆盖时完全继承父引用；覆盖只影响新子任务调度。
5. 普通键采用显式传播白名单：未授权传播、未知或值不满足快照安全性的键一律不继承；保留安全键不得由普通键覆盖。
6. Trace 必须保留 traceId 并新建 spanId；父 spanId 记录为关联父节点。
7. Security Identity 只传身份声明，任何授权结论不传。
8. Authorization 每次受保护资源操作都在当前身份、资源、动作及有效策略下重新评估。
9. Transaction 不跨任务自动传播。
10. Connection 不跨任务自动传播。

### 3.1 Context Values 白名单与对象别名（用户已裁决 A）

类型化键的传播权限在受信任的键定义位置声明，默认禁止传播；调用方无权为其他模块定义的键临时开启传播。获准传播的值必须满足以下条件之一：深不可变；显式声明且验证为跨任务共享安全；或提供派生子值的快照/复制机制。仅仅将可变对象放进不可变映射不构成安全传播。

派生时逐项验证：不符合规则的父键默认不进入子上下文；若调用方明确要求传播不安全键，则在子任务创建前以上下文构造错误拒绝，禁止悄悄共享引用。子任务自定义键不能伪装身份、授权、Deadline、Cancellation、事务或连接等保留元素。共享对象的内部状态可以变化，但上下文的键和值绑定不可变，且其并发安全责任由声明的共享策略保证。

## 4. 取消与清理语义

取消是请求，不是线程杀死或任意指令处异步抛异常。取消状态可以立即置位，但**取消异常仅在语言定义的挂起点/显式取消检查点观察并生效**；已就绪的挂起操作也须执行检查。进入挂起点时先检查父令牌及截止时间；截止时间已到时产生取消原因 `DeadlineExceeded`，普通请求为 `Cancelled`。重复取消幂等，首个已确定的取消原因保持稳定；失败原因独立保存。

不可取消区间只用于有限时长的资源状态修复与最终清理，不能包围一般业务计算或无界 I/O。概念标记 `nonCancellable(maxDuration)`（草案）要求显式有限预算：有效上限为 min(显式预算, 运行时允许的清理预算)，预算耗尽后恢复取消检查；不得以嵌套区间延长外层截止。清理有效预算固定为全局运行时上限与局部显式上限两者的最小值（用户已裁决 A），局部不得延长全局上限。区间内若调用无法保证限时返回的阻塞 API，运行时必须拒绝声明为有界保证，或报告无法保证限时清理。不可取消区间仅延迟取消观察，不撤销父取消和 Deadline。

不可取消区间首次进入时由单调时钟启动预算；嵌套区间共用剩余额度且不得重置计时。预算耗尽后，运行时必须恢复协作取消检查并报告清理未完成状态；对于无法中断的阻塞操作只能报告超限，不能虚称强制终止。运行时内部关键资源修复如确需特殊策略，应经独立、受信任的资源管理能力明确授权，并暴露运行时无法严格限时的事实；普通业务 API 不得获得无限预算。取消后的清理不得恢复业务正常执行，仍须保存原始取消原因与清理失败。

作用域退出的保证是：请求取消、触发已注册的 finally/资源释放、等待所有已启动子任务完成或报告无法终止；不承诺外部系统故障、永久阻塞或进程终止下的绝对清理完成。清理失败不得吞没原始失败，应进入聚合结果。普通取消通过独立的 `CancellationException`（草案）通道报告，业务异常保持其原始类型；超时是携带 DeadlineExceeded 原因的取消，不伪装成业务异常。取消不得默认触发普通作用域的“子业务失败”级联。

## 5. 失败传播与聚合

| 事件 | 普通 TaskGroup | supervisor TaskGroup |
| --- | --- | --- |
| 子任务业务异常 | 记录失败，立即请求取消其他未终止子任务，等待全部子任务清理 | 记录该子失败，不取消兄弟任务，等待全部子任务结束 |
| 子任务普通取消 | 只标记该子取消；若为父取消则沿父子令牌传播 | 同左 |
| 父作用域业务异常 | 请求取消全部子任务，等待回收，保留父异常为主异常 | 同左；监督只隔离子任务之间的失败 |
| 父作用域取消/Deadline | 请求取消全部子任务，等待回收 | 同左 |
| 作用域正常结束 | 等待所有子任务并汇总失败 | 等待所有子任务并汇总失败 |

聚合采用确定性顺序：若父作用域已有业务异常，则其为 primary；否则按子任务**创建序号最小**的业务失败作为 primary；其余业务失败与清理失败按任务创建序号、同任务发生序号进入 suppressed；取消原因单独存放，不作为业务 primary。没有业务失败而存在清理失败时，最早清理失败为 primary。仅存在取消时报告 `CancellationException`；无失败且无取消时成功。**监督作用域裁决 B**：已由调用方显式确认处理的子业务失败，不再进入作用域退出时的“未处理异常”聚合；未确认处理的失败统一聚合，不能静默丢弃。单纯 `await()` 获取异常或读取 `isDone()` 均不等于已处理；确认动作必须针对该 Future 的已完成失败执行，且仅可成功一次。处理确认与作用域关闭须原子排序：在作用域进入最终聚合快照之前完成确认的失败被排除，快照形成后确认不改变该次聚合。父作用域自身抛出的异常不受子任务确认状态影响；普通 TaskGroup 的子失败仍按规定触发兄弟取消，即使后来被标记已处理。清理失败一律留在聚合中，确认业务异常不能吞没清理失败。取消原因不作为“未处理业务异常”。

## 6. 对外 API 映射（以下全部签名均为草案，不是现有 Jasper 语法或实现）

- `Future<T>`（公开，草案）：`await(): T`、`isDone(): bool`、`cancel(): bool`、`acknowledgeFailure(): bool`；最后一项仅在业务失败已确定后显式确认其已处理，成功确认返回 true，重复确认或没有业务失败返回 false。它是 Jasper 异步结果句柄，不要求暴露 JVM 原生 Future 类型。
- `TaskGroup`（公开，草案）：`run(scope: ScopeBody): R`、`supervisor(scope: ScopeBody): R`、`spawn<T>(operation: AsyncOperation<T>, options: ChildOptions?): Future<T>`；作用域正常退出必须 join 所有子任务。
- `Task`（内部，草案）：`id: TaskId`、`context: CoroutineContext`、`state: TaskState`、`continuation: Continuation`；仅调度器管理。
- `CoroutineContext`（公开只读视图，草案）：`get<T>(key: ContextKey<T>): T?`、`with<T>(key: ContextKey<T>, value: T): CoroutineContext`；with 返回新快照。
- `ChildOptions`（公开，草案）：`deadline?: Deadline`、`executor?: ExecutorRef`、`values?: ContextValues`。

`await` 的具体语法形态留待既有语言规范协调；此处仅规定可观察语义。任务创建只经结构化作用域入口，不引入额外的语言级启动关键字。禁止隐式脱离父作用域的 fire-and-forget；若未来确需后台服务任务，应有独立、显式拥有者和关闭契约。

## 7. Java 8 第一版落地约束

JVM 第一版仅使用 Java 8 可用的 `ExecutorService`、线程池、`java.util.concurrent.Future`、同步原语和运行时自有状态机；不得依赖虚拟线程、Java 21+ StructuredTaskScope 或后续 JDK API。公开 `Future<T>` 与 JVM Future 之间通过适配器映射，不泄漏 JVM 特定异常或线程句柄。

编译器后续须将可挂起执行段转换为显式 continuation/状态机；在线程池中调度就绪 continuation，挂起时登记完成回调并释放工作线程，完成后重新入队。不得以“每个协程占用一个阻塞线程等待 Future.get()”冒充真正的非阻塞挂起。对无法改造成异步的阻塞 I/O，使用有容量限制的隔离阻塞池，并说明其无法提供硬性取消时延保证。TaskGroup 以计数、完成通知和父子注册表实现 join；注册与作用域关闭必须原子协调，关闭后拒绝新增子任务。超时使用单调时钟和可取消定时器；线程中断仅是可选优化，不是取消正确性的前提。

## 8. Executor 平台端口（所有签名均为草案）

| 端口 | 概念签名（草案） | 契约 |
| --- | --- | --- |
| schedule | `schedule(taskId, continuation): ScheduleResult` | 将可运行 continuation 入队；不得同步重复执行同一 continuation |
| yield | `yield(taskId, continuation): ScheduleResult` | 当前任务自愿让出执行权，重新进入公平调度队列 |
| cancel | `cancel(taskId, reason): CancelResult` | 幂等设置取消请求并唤醒可取消挂起点；不强制杀线程 |
| completion | `completion(taskId, outcome): CompletionResult` | 恰好一次发布终态、唤醒等待者并通知父 TaskGroup |

JVM 适配器负责线程池、计时器、唤醒与 Java 8 Future 桥接；平台适配器只提供调度、时钟与完成通知能力。未来 Jasper OS 适配器可以替换底层调度与事件源，但不能改变上下文继承、异常类型、父子回收、取消观察点和聚合顺序；本文不规定任何操作系统内部实现。适配器必须保证同一 continuation 不并发恢复、完成仅发布一次、关闭后调度请求可被明确拒绝，拒绝必须转换为可观察的任务失败并由作用域回收。

## 9. 补充的运行时基础契约（S4-B 前置设计与分期实现边界）

以下十项补足并发正确性、背压与可维护性。其中前五项属于第一版实现前必须落实的语义；其余五项至少固定接口边界，可分阶段提供完整功能。所有示例类型/签名均为草案。

### 9.1 协程状态机与原子转换（P0）

任务生命周期为 Created → Scheduled → Running ↔ Suspended → Completing → Completed / Failed / Cancelled。终态互斥且不可逆，状态转换必须线性化；同一个 continuation 任意时刻最多一个执行者，任何挂起登记与唤醒必须遵守“先登记、后检查完成，或等效无丢失通知”协议。终态恰好发布一次。任务执行身份独立于线程，恢复时不保证回到原线程。

### 9.2 有界背压与资源配额（P0）

分别限制运行中的任务数、等待调度数、已挂起任务数及作用域内已创建但未结束的任务数；四类配额不可用线程池大小混同。提交超出配额时须使用显式声明的背压策略（等待容量、立即拒绝或有界队列），不得无界增长或静默丢任务。等待容量本身必须可取消、受 Deadline 约束，且不得在调度器工作线程内阻塞等待。拒绝创建的任务不得被登记为活动子任务，不得产生无法回收的 Future。

### 9.3 挂起安全、锁与资源所有权（P0）

线程亲和的锁不得跨可能挂起的点持有；协程感知的互斥同步原语必须具备挂起等待而不占用工作线程的能力。只有声明允许跨挂起的资源所有权才能随任务持续；资源借用、锁释放和取消回滚须有明确顺序。编译器后续可增加静态诊断，运行时对无法静态判断的危险模式提供诊断；不得声称在无界外部操作上可以自动消除死锁。

### 9.4 ThreadLocal 与上下文隔离（P0）

CoroutineContext 以任务为归属，不能借助 JVM ThreadLocal 作为语义上的唯一存储。线程池适配器在进入任务执行片段时绑定必要的桥接值，退出时必须在 finally 中还原或清除；不得将前一任务的安全身份、日志或 Trace 泄漏到下一任务。Java 原生 ThreadLocal 不默认随协程迁移；如需桥接外部库，应有明确作用域和可验证的清理机制。

### 9.5 取消、完成与失败竞争（P0）

取消请求与终态发布是不同事件：任务已终结后 cancel 不得改变终态，且应报告“未接受新的取消请求”；运行任务接收到取消只设置请求与唤醒检查点，不直接发布 Cancelled。谁先获得终态发布线性化点，谁决定最终终态；在取消检查点观察到取消后走清理路径，清理中的业务失败及清理失败按现有聚合规则处理，不能隐式覆盖已发布终态。截止时间到达是发出取消请求，不等价于任务立即完成。

### 9.6 异步同步原语（P1）

后续对外规范统一 Mutex、Semaphore、Channel 的协程可挂起等待、取消移除等待者、公平性与关闭唤醒协议（名称均为草案）。第一版若尚未提供某一原语，不得将阻塞式 Java 锁包装成“非阻塞协程原语”宣称完成。

### 9.7 调度优先级和公平性（P1）

Executor 端口应允许扩展优先级与让出提示（均为草案），但第一版默认同优先级任务公平轮转，不保证硬实时和精确执行顺序。优先级不能突破父任务取消、任务配额与安全上下文边界；连续高优先级负载的饥饿预防策略需由适配器单独明示并测试。

### 9.8 阻塞调用隔离（P1）

阻塞 I/O、外部同步 API 和 CPU 密集型工作必须与可挂起 continuation 调度明确区分。无法非阻塞化的调用须使用容量受限的独立执行资源，满载时按明示的背压规则处理；隔离不意味着调用可被强制取消，也不意味着清理预算能中断阻塞系统调用。

### 9.9 协程可观测性与诊断（P1）

定义任务 ID、父任务 ID、作用域 ID、创建时间、最后一次挂起原因、取消请求原因及最终结果的结构化诊断字段（概念字段，均为草案）。Trace 仅用于跨链路关联，不替代父子任务树。诊断接口默认不得暴露 Context Values 的敏感内容，不得以读取诊断数据改变任务执行语义。

### 9.10 作用域所有权与资源生命周期（P1）

每个 Task 必须有且仅有一个活动的结构化父作用域；关闭作用域的动作先封闭新增子任务入口，再等待全部已注册子任务终态和清理。Future 可在作用域外保存结果引用，但不得因此延长已结束作用域的执行权限或让子任务逃逸。外部长期后台服务任务仅能由显式生命周期拥有者管理，并拥有可观测的停止、取消与回收契约；本阶段不新增无主任务 API。

## 10. S4-B 验收判定

- 创建两个子任务时各自身份唯一、父链正确；父取消传播、子取消不反传。
- 子 Deadline 不晚于父；父期限已过的子任务在首个检查点取消。
- 普通键传播白名单有效，未知键、事务、连接及授权缓存不能继承。
- 身份可见但每次资源操作重新授权；Trace 保持 traceId 且新建 span。
- 普通组首个业务失败触发兄弟取消；监督组不因子业务失败取消兄弟；两者都等待回收。
- 多个失败以创建序号稳定聚合；取消与业务异常可区分；清理异常不丢失。
- 无界阻塞不能宣称有界取消；Java 8 环境不依赖新 JDK 功能。
- 同一 continuation 无并发双恢复、任务完成仅一次、关闭后禁止新增子任务。

## 11. 用户已裁决的三项策略（2026-10-24）

1. **监督作用域失败处理：B，已裁决。** 已显式确认处理的子任务业务异常退出作用域时不再聚合；未确认处理的异常必须聚合。确认必须发生在最终聚合快照前；读取或捕获异常不自动确认。普通组的兄弟取消策略不受确认影响。
2. **Context Values 传播：A，已裁决。** 类型化传播白名单为唯一自动继承方式；未知键和未显式允许的键不传播，获准的值仍须满足不可变、独立快照或显式并发安全条件。
3. **不可取消清理预算：A，已裁决。** 全局与局部预算取最小值，嵌套不重置；普通业务不能突破全局上限；超过预算不承诺可以强制结束外部阻塞。

这三项不再列为待用户裁决的问题。未来如调整须通过新的设计变更说明显式重新裁决。

## 12. S4-B 增补验收项

- 监督组：`await` 捕获但未确认的失败仍被聚合；显式确认在聚合快照前生效；快照后的确认不反向修改结果；清理失败不能由确认动作吞没。
- 白名单：未知键、未标记键不能继承；可变对象无复制/共享安全策略时不能被强制传播；普通键不能伪装保留上下文元素。
- 清理预算：使用单调时钟、全局与局部取最小、嵌套不得重置；无法中断的阻塞操作只能报告限制而不能保证强制终止。
- 生命周期竞争：双重恢复、取消与完成交错、完成回调重复、挂起登记与完成竞态均须通过压力测试。
- 背压：有限队列、满载等待/拒绝、取消等待、作用域关闭并发创建均有确定行为。
- 挂起安全：线程亲和锁持有期间的挂起可被禁止或诊断；ThreadLocal 桥接在协程切换后没有跨任务泄漏。
- 诊断与所有权：任务树、挂起原因与终态可追踪；作用域关闭后没有无主活动子任务。


## S4-B 运行时回调异常契约（2026-10-25）

`Future.complete/fail/cancel` 与 `CancellationToken.cancel` 先发布状态，再在锁外
按注册顺序尝试该批次全部回调。一个回调抛错不得阻止后续通知或父子取消传播。
全部尝试后，有失败则向发布者抛 `CallbackDispatchError`：`message()` 是首个失败文本，
`failureCount()` 是本批失败注册者数。嵌套批次按一个失败项计，不保存 Error/Throwable
对象；成功发布的终态不回滚，重复发布仍返回 false。

终态后 `onComplete` 或已取消后 `onCancel` 的即时单项通知继续直接传播原始异常。
异步执行器中回调异常的接收方是发布该通知的执行线程；它不改写业务 Future 的既有结果。

`TaskGroup.cancel` 即使根令牌通知失败，也必须尝试取消全部兄弟 Future，再汇总报错。
任务失败后的级联取消与任务 settled 标记使用嵌套 finally 保证：失败通知抛错不能跳过
级联取消，级联通知抛错不能跳过 settled。调度被拒绝时同样适用；close 仍按业务失败
快照聚合，等待真实任务体退出。

本契约不承诺中断阻塞或不返回的回调，不保证 JVM 资源耗尽时仍能分配汇总错误。
