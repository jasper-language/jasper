# 第三章：类型系统

## 3.1 设计原则

Jasper 是 GC 变量安全语言。类型系统第一版只保留能形成清晰心智模型的核心语法：

```jasper
T          // 普通非空引用/值类型
T?         // 可空类型
*T         // GC 安全指针类型
T[]        // 数组
List<T>    // 泛型
(A, B)     // tuple 类型
```

明确不支持：

```jasper
T!
T??
&T
&&T
raw T
shared T
```

`??` 只属于表达式层 null coalescing，不属于类型语法。

## 3.2 基本类型

```jasper
var a: int8 = -128;
var b: int16 = -32768;
var c: int32 = 42;
var d: int64 = 9223372036854775807L;

var u: uint32 = 1;
var f: float64 = 3.14;
var ok: bool = true;
var ch: char = 'A';

var s: string = "hello";
var bytesValue: bytes = b"\x00\x01";
var pattern: regex = r"\d+";
var value: any = 42;
```

短名是**固定宽度**的别名，与任何平台无关（收敛方案 A5，2026-10-14 定稿）：

| 短名 | 等价于 | 说明 |
|------|--------|------|
| `int` | `int32` | 与 C/Java/C# 的 `int` 一致 |
| `uint` | `uint32` | 同上 |
| `float` | `float32` | C/Java/C#/GPU 的 `float` 一律单精度；64 位写 `float64` |
| `char` | `char32` | 32 位 Unicode scalar value |
| `byte` | `uint8` | 无符号字节；字节序列 `bytes` 的元素无符号 |

**当前 JVM 后端的实现状态**（2026-11-10）：`int8`、`int16`、`int32`、`int64`、`float32`、`float64`、`bool`
已按规范实现，别名 `int` / `float` 在编译器前端归一到规范名。`byte` 按规范是无符号 8 位：任何读出（数组元素、
字段、方法返回、转换、集合元素）都是 0..255，`cast x as byte` 取低 8 位，与其它窄类型运算时先提升为 `int32`；
JVM 上仍存成 `byte` / `byte[]`，与平台 API 互通（平台给出的字节按无符号读）。`char` 按规范是 32 位 Unicode
scalar：字面量保留完整码点（`'😀'` 是 U+1F600），JVM 上存成 int / `int[]`，拼接、打印、`toString` 按字符输出；
传给平台 API 的 `char` 形参时按 16 位码元传递（BMP 以外的码点会被截断，是与平台互通的边界）。`cast` 到 `char`
和 `char` 的自增减不校验 scalar 范围（不拒绝代理区或超过 U+10FFFF 的值）。`uint8`～`uint64`、`int128`、`uint128`、`char8` / `char16` / `char32`、`float128`
尚未实现，写出来会得到编译错误 `Type '…' is specified but not yet supported by the JVM backend`（`uint` 报 `uint32`）。

## 3.3 可空类型

默认类型非空：

```jasper
var name: string = "Ada";
```

只有显式 `?` 类型可以为 `null`：

```jasper
var maybeName: string? = null;
```

类型层没有 `!`，因为非空是默认规则；类型层也没有 `??`。

基本类型的可空形式（`int32?`）在 JVM 上是对应的包装类。它不能直接参与算术、排序比较或作条件，先用 `??` 取值：

```jasper
var count: int32? = null;
var total: int32 = (count ?? 0) + 1;
```

`int32?` 不隐式转换为 `int64?`；需要时写 `x ?? 0` 取值后再拓宽。

## 3.4 指针类型

`*T` 是 GC 管理下的安全指针类型：

```jasper
var x: int32 = 1;
var p: *int32 = &x;
var y: int32 = *p;
```

规则：

- `*T` 是类型。
- `&expr` 是取地址表达式，结果类型为 `*T`。
- `*expr` 是解引用表达式，结果类型为 `T`。
- Jasper 没有 `unsafe` 语法。
- Jasper 没有 `&T` 引用类型。

## 3.5 数组

数组使用后缀 `[]`：

```jasper
var xs: int32[] = [1, 2, 3];
var matrix: int32[][] = [[1, 2], [3, 4]];
var nullableItems: (string?)[] = [null, "x"];
```

容器语义要点（详见第十一章）：

- `T[]` 是**定长**类型，且与 `List<T>` 是**两个不同类型**，不可互换。
- `List<T>` / `MutableList<T>` 采用 Kotlin 式只读/可变分家。
- `Set`、`dict` **插入有序**（按插入顺序迭代）。
- `Map<K,V>` 是**可变接口**；`dict<K,V>` 是它的**插入有序具体实现**。**不设 `MutableMap`**，读写权限由语言机制管理（W-17，2026-10-20 裁决）。
- `{}` 可作为**声明初始化时**的 `dict` 语法糖；该写法**已裁决、文法尚未落实**，在实现前不能视为可用语法。
- **无 COW**（不做写时复制）。
- `const` 只约束绑定本身，**不约束容器内容**（`const xs: int32[]` 仍可改元素）。
- v1 **没有切片视图**（`xs[1:3]` 之类的视图语法不进入核心）。

## 3.6 泛型

泛型类型实参使用 `<...>`：

```jasper
var names: List<string> = new List<string>();
var table: Map<string, int32> = new dict<string, int32>();
// 已裁决、未实现：var table: Map<string, int32> = {};
```

接口不能 `new`，因此 `Map` 变量由 `dict` 实现初始化。`{}` 作为声明初始化时的
`dict` 语法糖**已裁决、文法尚未落实**；在文法实现前，不能把它当作已可用语法。

泛型声明：

```jasper
class Box<T> {
    public var value: T;
}

function first<T>(items: T[]): T? {
    return items[0];
}
```

泛型约束使用 `extends` 或 `where`：

```jasper
function max<T extends Comparable<T> >(a: T, b: T): T {
    return a;
}

function sort<T>(items: T[]): T[]
where T is Comparable {
    return items;
}
```

> 注意：lexer 把 `>>` 识别为右移运算符，因此嵌套泛型实参的收尾需要
> 在最后两个 `>` 之间加空格（写 `Comparable<T> >`，不能写 `Comparable<T>>`）。

## 3.7 Tuple

Tuple 类型使用括号和逗号：

```jasper
var pair: (string, int32) = ("Ada", 36);
var nested: (string, (int32, bool)) = ("x", (1, true));
```

括号分组和 tuple 的区别：

```jasper
(a)       // 分组，不是 tuple
(a, b)    // tuple
(a,)      // 非法：第一版不支持单元素 tuple
```

Tuple 可用于多值返回：

```jasper
function userInfo(): (string, int32) {
    return "Ada", 36;
}
```

Tuple 访问使用索引：

```jasper
var pair: (string, int32) = ("Ada", 36);
var name: string = pair[0];
var age: int32 = pair[1];
```

普通变量声明不使用 `var (a, b) = pair` 形式；多返回/多赋值使用 `var a, b = pair`（规则见 §4.3.1）。

### 3.7.1 当前实现（Q223，2026-11-10）

- 下标必须是整数字面量，且在 `0..元数-1` 内；变量下标或越界是编译错误。
- 元组字面量有期望类型时（变量声明、赋值、`return`），元素按期望元素类型检查并转换：
  `var p: (int64, float64) = (1, 2);` 合法，1 按 int64 存。
- 已有的元组值赋给另一元组类型时，元数必须相同，元素逐个兼容；但两侧都是基本类型（或其可空形式）的元素必须**同名**，
  不做元素级数值拓宽：`(int32, int32)` 的值不能赋给 `(int64, int64)`，需要时逐元素取出再组合。
- 元组暂无相等与字符串形式：`==` / `!=`、`+`（含字符串拼接）、插值、`print` / `println` 用在元组上都是编译错误，
  请对元素操作。这些是「更严、可放宽」的临时规则，规范补上元组相等与字符串形式后再放开。
- void 不能作元组元素。
- JVM 表示：元组值是装箱元素组成的 `Object[]`，元素按声明类型读回（拆箱、`byte` 取 0..255、`char` 为码点）。
  公开 `.jaso` 签名里的元组类型照旧被诊断（docs/jaso.md）。

## 3.8 Any 与泛型通配

`any` 是顶层类型，也用于泛型通配：

```jasper
var values: List<any> = new List<any>();
var animals: List<any extends Animal> = getAnimals();
var sinks: List<any super Dog> = getDogSinks();
```

`?` 只用于 nullable，不用于泛型 wildcard。

## 3.9 保留关键字

以下关键字是**词法 token，但 parser 零引用**（保留但未启用）：

```text
raw shared weak auto unique atomic pointer handle locked delete destructor
```

它们不能用于变量名、类型名或修饰符，也不进入类型规则。
当前裁决**不启用 GC/所有权超集**（详见第十一章）。
W-21（2026-10-20）：保留词维持现状，不赋予新语义，不废弃。

### 3.9.1 运算符

运算符行为由语言规范统一定义，**不支持用户自定义运算符重载**（2026-10-20 裁决）。

## 3.10 语法对照

| 特性 | Parser 规则 | 示例 |
|------|-------------|------|
| 基本类型 | `primitiveType` | `int32`, `float64`, `bool` |
| 命名类型 | `typeAtomBase` | `User`, `List<T>` |
| 可空类型 | `typeQualifier` | `string?` |
| 指针类型 | `typePrefix` | `*int32`, `**Node` |
| 数组类型 | `typeSuffix` | `int32[]` |
| 泛型实参 | `typeArguments` | `Map<string, int32>` |
| 泛型通配 | `wildcard` | `any`, `any extends T`, `any super T` |
| Tuple | `typeAtomBase` | `(string, int32)` |
