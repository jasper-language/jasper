# 第五章：函数

## 5.1 函数声明

Jasper 使用 `function` 声明函数，返回类型放在参数列表之后：

```jasper
function add(a: int32, b: int32): int32 {
    return a + b;
}

function log(msg: string): void {
    println(msg);
}
```

省略返回类型等价于 `void`：

```jasper
function noop() { }
```

## 5.2 参数

参数使用统一绑定语法 `name: Type`：

```jasper
function move(x: int32, y: int32): void {
}
```

参数类型可由后续设计决定是否允许省略；当前推荐显式写出。

## 5.3 多值返回

多值返回使用 tuple 类型：

```jasper
function divide(a: int32, b: int32): (int32, int32) {
    return a / b, a % b;
}

var q, r = divide(17, 5);
```

`return a, b` 按 Go 风格视为多返回；`var a, b = expr` 按位置绑定多返回值，数量必须匹配。

## 5.4 方法和构造器

类内函数仍使用 `function`：

```jasper
class Counter {
    private var value: int32 = 0;

    public constructor(initial: int32) {
        this.value = initial;
    }

    public function inc(): void {
        this.value = this.value + 1;
    }
}
```

> 方法体内使用 `this` 引用当前实例（`this` 是关键字，`super` 同理）。

## 5.5 Lambda

Lambda 使用 `lambda (...) { ... }`。

```jasper
var zero = lambda () {
    return 0;
};

var add = lambda (a: int32, b: int32) {
    return a + b;
};

var sum = lambda (a, b) {
    return a + b;
};
```

Lambda 参数必须使用括号；不支持单参数无括号 lambda。

对应 parser：

```antlr
lambdaExpression
    : Lambda lambdaParameters block
    ;

lambdaParameters
    : '(' ( Identifier (',' Identifier)* ','? )? ')'                 #LambdaParamsInferredList
    | '(' plist=functionParameterList? ')'                           #LambdaParamsTypedList
    ;

```

Lambda 是匿名表达式，不能带 identifier，也不在 lambda 语法里声明返回类型。返回类型由左侧目标类型或 checker 推断。

```jasper
var f: *T = lambda () {
    return value;
};
```

## 5.6 泛型函数

```jasper
function first<T>(items: T[]): T? {
    return items[0];
}

function max<T extends Comparable<T> >(a: T, b: T): T {
    return a;
}
```

> 注意：`>>` 会被 lexer 识别为右移运算符，嵌套泛型的收尾要写成 `Comparable<T> >`。

`where` 可用于额外约束：

```jasper
function sort<T>(items: T[]): T[]
where T is Comparable {
    return items;
}
```

## 5.7 异常声明

Jasper 当前确认异常控制流使用：

```jasper
throw expr;
try { } catch (e: Error) { } finally { }
```

`throws` 保留为函数签名元信息，不做 checked exception。它可供 IDE、文档生成、静态分析使用，但不强制调用方 `catch`。

```jasper
function read(path: string): string throws IOException {
    return "";
}
```

实际异常控制流仍然只由 `throw + try/catch/finally` 表达。

错误模型遵循 W-18（2026-10-20 裁决）：

- **异常是主要机制**：`Error` 是错误层次根，`RecoverableError` / `FatalError` 是两个分支。
- `Result<T, E>` 只用于「失败本身是正常业务数据」的 API；可恢复错误与致命错误走异常。
- 同一操作只提供一种错误契约：不提供「抛异常」与「返回 `Result`」两套平行 API。
- 错误模型是 Jasper 的语言语义，不依赖 JVM 的 `Throwable`；JVM 只是当前后端的内部实现。

错误不是值（2026-10-24 裁决）：

`Error` / `RecoverableError` / `FatalError` 及其子类是**控制流载体**，不是普通返回值。
它们只能出现在 `throw new X(...)` 与 `catch (e: X)` 中，不得作为函数返回类型、元组元素、
字段类型、参数类型、局部变量类型或泛型实参：

```jasper
// 编译期错误：error is not a value
function read(): (int32, Error) { ... }
function read(): Error { ... }
var lastError: Error;
function handle(e: Error): void { ... }
var box: Result<int32, Error>;
```

多值返回本身不受影响：`(int32, int32)`、`(string, bool)` 等业务数据元组照旧可用。
`Result<T, E>` 的 `E` 必须是业务数据类型（如 `ParseFailure`），不能是错误类型。
调用方也不能用 Go 式「先拿错误值、再 `if (err ...)` 逐个判断」的流程；失败应通过
`throw` 传播，由 `try` / `catch` 统一处理：

```jasper
// 禁止：错误被当成普通返回值
var value, err = parse(text);
if (err != null) { ... }

// 正确：错误通过异常传播
try {
    var value = parse(text);
} catch (e: RecoverableError) {
    ...
}
```
